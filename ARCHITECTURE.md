# Архитектура

Программа распределяет фотографии по книгам и разворотам, присваивает им имена файлов и
выгружает копии в папку для печати. Исходные файлы читаются и не изменяются.

Состояние на 2026-11-09: выпуск 2.0.0, оболочка на Avalonia. Вторая оболочка (WPF)
удалена из решения — см. [0009](docs/decisions/0009-wpf-shell-removed.md).

---

## 1. Проекты

```
PhotoBookRenamer.sln
│
├── src/
│   ├── PhotoBook.Core/                  правила предметной области
│   ├── PhotoBook.Application/           сценарии и порты
│   ├── PhotoBook.Infrastructure/        диск, JSON, изображения, журнал, GitHub
│   ├── PhotoBook.Presentation/          модели представления и команды
│   └── PhotoBook.Desktop.Avalonia/      оболочка: представления, стили, точка сборки
│
└── tests/
    └── PhotoBook.Application.Tests/
```

Имя сборки оболочки — `PhotoBookRenamer`: от него зависят установщик, ярлык,
автообновление и пути в `scripts\`.

| Проект | Содержит | Не содержит |
|---|---|---|
| `Core` | `Book`, `Page`, `Project`, раскладка разворотов, правила проверки папок, план выгрузки | интерфейс, файловую систему, журнал, `ObservableCollection` |
| `Application` | сценарии и порты | конкретных технологий |
| `Infrastructure` | реализации портов: файлы, изображения, проекты, журнал, обновления | UI-фреймворк |
| `Presentation` | модели представления, команды, конвертеры, помощники | представления, диалоги, доступ к диску |
| `Desktop.Avalonia` | представления, стили, диалоги, точка сборки | правила предметной области |

`Core`, `Application`, `Infrastructure`, `Presentation` собираются на `net8.0` без
Windows-зависимостей: `using System.Windows;` в них — ошибка компиляции, а не замечание
на ревью.

Зависимости направлены внутрь: `Desktop.Avalonia` → `Presentation` → `Application` →
`Core`. `Infrastructure` ссылается на `Application` и `Core`. Правило проверяется
компилятором.

Реализации портов объявлены `internal`, `InternalsVisibleTo` есть только у тестов:
поэтому ни представление, ни диалог, ни конвертер не могут построить `FileService` или
`ExportService`. Каждый слой собирает себя сам (`ApplicationServices`,
`InfrastructureServices`), и точка сборки вызывает два метода вместо десятка классов.

Пакеты: `Core` — ни одного. `Application` — только абстракции внедрения зависимостей.
`Infrastructure` — ImageSharp, Octokit, журнал. `Presentation` — CommunityToolkit.Mvvm.
Оболочка — Avalonia и контейнер.

## 2. Порты

`Application` объявляет интерфейсы, реализации находятся в `Infrastructure`, кроме тех,
что требуют окна.

| Порт | Назначение |
|---|---|
| `IFileService` | файлы и папки |
| `IImageService` | размеры фотографии, выбор обложки |
| `IThumbnailProvider` | уменьшенная копия фотографии |
| `IPickFiles` | выбор папки и файла |
| `IProjectRepository` | чтение и запись проектов |
| `ILoggingService` | журнал |
| `IUpdateFeed` | проверка обновлений |
| `IProjectDialogs`, `IScreenViewFactory` | диалоги и экраны |

`IPickFiles`, `IProjectDialogs` и `IScreenViewFactory` реализованы в оболочке: вопрос к
человеку и показ окна требуют окна. Остальные реализует `Infrastructure`.

Стоимость операции — свойство адаптера, а не ядра: у `IThumbnailProvider` возможны
реализации с разной стоимостью, выбор фиксируется замером.

## 3. Правила реализации

| Правило | Следствие |
|---|---|
| Ошибка — значение, а не исключение | `Result<T>` с текстом ошибки; исключения не используются для ожидаемых отказов |
| Долгая работа принимает `CancellationToken` | отмена при закрытии экрана |
| Зависимости через конструктор | контейнер доступен только в точке сборки; модели представления получают зависимости в конструкторе |
| Наблюдаемость — в оболочке | `Core` возвращает `IReadOnlyList<T>` |
| Один источник истины | путь к уменьшенной копии и имя файла при выгрузке вычисляются в одном месте |
| MVVM без ручного кода | исходные генераторы вместо ручных `OnPropertyChanged` |
| Типизированная команда получает свой аргумент | чужой аргумент — отказ до `CanExecute` (`CommandTypeHelper`), иначе исключение |
| Долгая работа не идёт по потоку интерфейса | заполнение миниатюр, декодирование и чтение проекта — на рабочем потоке |

## 4. Контракты

| Контракт | Место | Проверка |
|---|---|---|
| Имя файла при выгрузке: `001-00.jpg` | `ExportService.GenerateFileName` | тест контракта |
| Формат файла проекта | `ProjectRepository` | тест совместимости с проектом 1.1.x |
| Путь данных `%LOCALAPPDATA%\PhotoBookRenamer` | `Infrastructure` | сценарии |

Формат проекта, имена файлов и путь данных не менялись между 1.1.x и 2.0.0.

## 5. Производительность

Ячейка отображается в размере около 190 пикселей при исходных файлах в 24 Мпикс.
Стоимость определяется декодированием JPEG: уменьшенная копия строится один раз и
переиспользуется, а карточка списка проектов не читает оригинал вовсе.

| Сценарий | Значение | Чем измерено |
|---|---|---|
| Список проектов, 43 карточки, возврат из проекта | 0,6 с | `scripts/measure-project-load.ps1` |
| Список проектов, первый запуск программы | 2,4 с (включая запуск процесса) | `scripts/measure-project-load.ps1` |
| Комбинированный, 50 книг × 20 разворотов, до разворотов на экране | 4,5 с | `scripts/perf-open-avalonia.ps1` |
| Уменьшенные копии, 374 фотографии (1,95 ГБ), первый раз | 11,0 с | `ThumbnailProvider` через стенд |
| Уменьшенные копии, повторно | 25 мс | там же |

Разбор измерений и история решений — `doc/PERF-2.0.md`.
