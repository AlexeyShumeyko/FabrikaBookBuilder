# Архитектура

Назначение программы: распределение фотографий по книгам и разворотам, присвоение имён
файлов и выгрузка копий в папку для печати. Исходные файлы не изменяются — программа
читает их и копирует по ссылкам.

**Состояние: 2026-10-03.** Разделы 1–5 описывают целевую структуру, к которой идёт
работа по [0001](docs/decisions/0001-ui-engine-avalonia.md). Раздел 6 описывает сборку и
проверки, действующие сейчас.

---

## 1. Проекты

```
PhotoBookRenamer.sln
│
├── src/
│   ├── PhotoBook.Core/                  правила предметной области
│   ├── PhotoBook.Application/           сценарии и порты
│   ├── PhotoBook.Infrastructure/        диск, JSON, изображения, журнал, GitHub
│   ├── PhotoBook.Desktop.Wpf/           оболочка WPF, удаляется после приёмки
│   └── PhotoBook.Desktop.Avalonia/      оболочка Avalonia
│
└── tests/
    ├── PhotoBook.Core.Tests/
    ├── PhotoBook.Application.Tests/
    └── PhotoBook.Infrastructure.Tests/
```

Правило зависимостей проверяется компилятором: `PhotoBook.Core` не имеет ссылок на
другие проекты.

| Проект | Содержит | Не содержит |
|---|---|---|
| `Core` | `Book`, `Page`, `Project`, раскладка разворотов, правила проверки папок, план выгрузки | интерфейс, файловую систему, журнал, `ObservableCollection` |
| `Application` | сценарии и порты | конкретных технологий |
| `Infrastructure` | реализации портов | WPF |
| `Desktop.*` | представление, привязки, диалоги | правила предметной области |

Зависимости направлены внутрь: `Desktop` → `Application` → `Core`.

## 2. Порты

`Application` объявляет интерфейсы, `Infrastructure` их реализует.

| Порт | Назначение |
|---|---|
| `IFileSystem` | файлы и папки |
| `IThumbnailProvider` | уменьшенная копия фотографии |
| `IPickFolder` | выбор папки |
| `IProjectRepository` | чтение и запись проектов |
| `ILogSink` | журнал |
| `IUpdateFeed` | проверка обновлений |

Стоимость операции — свойство адаптера, а не ядра. Для `IThumbnailProvider` существуют
две реализации с разной стоимостью; выбор фиксируется замером.

## 3. Правила реализации

| Правило | Следствие |
|---|---|
| Ошибка — значение, а не исключение | `Result<T>` с текстом ошибки; исключения не используются для ожидаемых отказов |
| Долгая работа принимает `CancellationToken` | Отмена при закрытии экрана |
| Зависимости через конструктор | `GetServiceProvider()` в моделях представления не используется |
| Наблюдаемость — в оболочке | `Core` возвращает `IReadOnlyList<T>` |
| Один источник истины | Путь к файлу превью и имя файла при выгрузке вычисляются в одном месте |
| MVVM без ручного кода | Исходные генераторы вместо ручных `OnPropertyChanged` |

## 4. Контракты

| Контракт | Место | Проверка |
|---|---|---|
| Имя файла при выгрузке: `001-00.jpg` | `ExportService.GenerateFileName` | тест контракта |
| Формат файла проекта | `Core`, сериализация проекта | тест совместимости с проектом предыдущей версии |
| Путь данных `%LOCALAPPDATA%\PhotoBookRenamer` | `Infrastructure` | сценарии |

## 5. Производительность

Ячейка интерфейса отображается в размере около 190 пикселей при исходных файлах в
24 Мпикс. Стоимость определяется декодированием, а не масштабированием: замена
алгоритма уменьшения меняет результат на 12 %.

| Сценарий | WPF | Цель |
|---|---|---|
| 20 книг по 9 фотографий, первый запуск | 41,9 с, пик 2,35 ГБ | единицы секунд, до 300 МБ |
| 20 книг, повторный запуск | 3,2 с | 0,5 с |

Измерения выполняются на реальных файлах скриптом `scripts\perf-open.ps1`. Текущие
значения хранятся в `doc/ROADMAP.md`.
