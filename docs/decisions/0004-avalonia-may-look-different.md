# 4. В версии на Avalonia внешний вид может отличаться

- Статус: принято
- Дата: 2026-10-03
- Связано с: [0001](0001-ui-engine-avalonia.md)

## Контекст

Для оболочки WPF действует правило: внешний вид неприкосновенен, любое отличие
считается браком. Оно проверяемо: движок известен, отличие означает ошибку реализации.

Avalonia — другой движок с другим набором возможностей: размытие тени, эффекты,
скругления, поведение окна без рамки. Воспроизведение поведения WPF средствами Avalonia
означало бы перенос его ограничений и отказ от возможностей нового движка.

## Решение

Для версии на Avalonia правило «внешний вид неприкосновенен» не применяется.

| Ситуация | Действие |
|---|---|
| Avalonia выполняет эффект иначе или лучше | Использовать возможности движка, зафиксировать отличие |
| Шрифт или ресурс требует другого способа подключения | Подключить средствами Avalonia, зафиксировать отличие |
| Отличие в несколько пикселей | Зафиксировать отличие |
| Эффект WPF не воспроизводим | Не воспроизводить, зафиксировать отличие |
| Новая возможность, которой не было в WPF | Считать изменением продукта, не связанным с переносом |

Каждое отличие фиксируется до применения: что отличается, как выглядит, почему так
и предпочтительнее.

Вне этого правила запрет на изменение сохраняется: поведение сценариев, формат
проекта, имена файлов при выгрузке, тексты интерфейса.

## Последствия

- О внешнем виде версии 2.0 сообщается в заметках релиза.
- Эталонные снимки экранов (`scripts/capture-golden.ps1`) остаются обязательными, но
  сравниваются по смыслу: тот же элемент, та же функция, подтверждённая осознанно.
- Функциональная проверка не ослабляется: сценарии из `scripts/` выполняются на
  каждом шаге без исключений.
