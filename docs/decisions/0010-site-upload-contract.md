# 10. Отправка на сайт: имена проектов, лимиты и число файлов в полёте

- Статус: принято
- Дата: 2026-11-19
- Связано с: [0008](0008-release-requires-sign-off.md)

## Контекст

Программа отправляет заказ на сайт через API платформы, которым пользуется и собственный
загрузчик сайта. Часть решений принимается не по документации, а по поведению платформы,
снятому запросами на тестовом аккаунте 2026-11-19:

| Вопрос | Что показала проверка |
|---|---|
| Имя проекта при создании | `title` в `creators/projects/create` игнорируется, проект создаётся пустым |
| Имя проекта в параметрах | `title` в `creators/projects/params` сохраняется и виден в списке аккаунта |
| Книг в одном проекте | загрузчик сайта не ставит книгу дальше позиции 50 (`common.starting.projectItemsLimit`) |
| Файлов в одном проекте | 501 файл принят платформой; 500 — предел собственного загрузчика сайта (`common.uploadFilesCountMax`) |
| Размер проекта | 1 ГиБ (`common.uploadFilesSizeMax`); на этом размере прогон получал 5xx на середине книги |
| Расширения | собственный загрузчик сайта принимает только `.jpg` и `.jpeg` |
| DPI и пиксели | сервер не проверяет: файл меньше рекомендованного принимается с `200`, размер проверяет клиент |
| `auth.whenUploading`, `auth.whenSaving` | у загрузчика книги оба флага `false`: вход требуется для аккаунта, а не для отдельной отправки |

## Решение

1. Каждый проект на сайте получает имя проекта из программы с постоянным префиксом
   `FFStudio`: `FFStudio: Лето 2026`. Префикс добавляется программой, в интерфейсе не
   настраивается и не показывается как отдельное поле.
2. Один проект сайта принимает не более 500 файлов, 1 ГиБ и 50 книг. Группа, которая не
   помещается, делится на несколько проектов; книга никогда не делится между проектами.
3. Файлы отправляются по четыре одновременно. Предел собственного загрузчика сайта — пять;
   четыре оставляют запас и снимают почти всё ожидание обработки одной страницы.
4. В отправку попадают только JPEG. Прочие расширения называются до начала отправки, а не
   отклоняются сайтом на середине прогона.
5. Перед первой записью проверяется регион: группа, собранная для одного сайта, не может быть
   создана в аккаунте другого.

## Обоснование

- Имя проекта — единственное, что отличает проект программы в списке аккаунта; без него
  клиент видит набор безымянных проектов рядом с проектами, сделанными на сайте.
- Лимиты взяты у собственного загрузчика сайта, а не у платформы: платформа принимает и 501
  файл, но проект за пределами лимитов загрузчика клиент не сможет открыть и отредактировать
  на сайте.
- Четыре файла в полёте — компромисс между скоростью и общей платформой для двух сайтов.
  Пять, как у сайта, не оставляют запаса; два давали до двух раз худшее время на большом
  тираже.
- Проверка расширения и размера на клиенте обязательна: сервер отвечает `200` и на файл,
  который не примет в производство.

## Правила

- Числа лимитов хранятся в одном месте (`UploadPlans`) и не дублируются в экранах.
- Изменение префикса или лимитов — отдельное решение, а не правка по месту.
- Контракт, снятый запросами, хранится в рабочих документах проекта; в репозиторий попадают
  только выводы, записанные здесь.
