# 6. Текст обновления — это текст для клиента

- **Статус:** принято
- **Дата:** 2026-10-03

## Контекст

В версии 1.1.0 окно обновления показывало пользователю служебный текст: адрес
GitHub-репозитория, имя учётной записи разработчика и ссылки на изменения. Виноват был
пайплайн — он дописывал к заметкам автоматический блок GitHub, а окно показывало текст
целиком.

Программа закупается компанией, и её обслуживает сотрудник, а не автор кода. Пользователю
не нужно знать, где лежит исходный код.

## Решение

1. Текст обновления пишется руками в `docs/release-notes/v<версия>.md` и целиком
   становится описанием релиза. Ничего не дописывается.
2. В тексте обновления не бывает ссылок, упоминаний и адресов репозитория.
3. Markdown умеет только то, что окно умеет показать: заголовки, выделения, списки,
   моноширинный текст. Таблицы, картинки и цитаты в заметках не используются.
4. Проверка выполняется автоматически на каждом пулреквесте и на каждом релизе.

## Последствия

- На странице релиза на GitHub нет списка изменений со ссылками на коммиты. Для
  разработчика это чуть меньше информации, для клиента — чище. Задача «кто что
  поменял» решается через историю коммитов.
- Автоматическая проверка ловит проблему раньше, чем её увидит клиент: она стоит в
  CI до слияния.
- Формат проекта и имена файлов при выгрузке не имеют отношения к этому правилу и
  остаются как есть.
