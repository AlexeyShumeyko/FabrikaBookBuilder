# 3. Две ветки: `master` и `integration/2.0`

- Статус: принято
- Дата: 2026-10-03

## Контекст

Перенос интерфейса на Avalonia выполняется волнами, невидимыми для пользователя
(см. `doc/ROADMAP.md`). Промежуточные сборки не должны попадать в релиз, а
исправления, приходящие из разработки, должны доходить до установленной версии.

Модель с одной веткой (`master` плюс короткие ветки задач) не подходит: она требует
выпускать каждое слитое изменение или копить их в неопределённой ветке.

## Решение

| Ветка | Содержимое | Когда изменяется |
|---|---|---|
| `master` | версия, доступная пользователям | при выпуске |
| `integration/2.0` | вся работа по переносу | постоянно |
| `feature/*`, `fix/*`, `refactor/*`, `chore/*`, `spike/*` | одна задача | от `integration/2.0`, обратно в неё |
| `hotfix/*` | исправление для установленной версии | от `master`, в `master` и в `integration/2.0` |

Требования:

1. Ветка задачи создаётся от `integration/2.0`. От `master` не создаётся.
2. `hotfix/*` применяется в `integration/2.0` в тот же день: иначе исправление
   вернётся в версии 2.0.0.
3. Сборка релиза выполняется только из `master`. Пайплайн не подписан ни на одну другую
   ветку.
4. Ветка удаляется после слияния.

## Последствия

- Релиз выпускается один раз за кампанию. Исправления, не признанные срочными,
  входят в него и не получают отдельных номеров.
- Расхождение веток ограничено тем, что волны 0–2 не меняют поведение: конфликты
  при слиянии `master` в кампанию не ожидаются.
- По мере роста кампании `integration/2.0` всё дальше от `master`; слияние выполняется
  по необходимости, а не автоматически.
