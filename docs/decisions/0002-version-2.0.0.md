# 2. Следующая версия — 2.0.0

- **Статус:** принято
- **Дата:** 2026-10-03

## Контекст

После переноса интерфейса на другой движок меняется всё, что пользователь видит:
перерисованы экраны, диалоги и списки, переписана загрузка изображений. Формат проекта
при этом не меняется, и имена файлов при выгрузке остаются прежними.

По строгому чтению правил SemVer это изменение на 1.x: совместимость не нарушена.

## Решение

Выпускаем **2.0.0**.

## Последствия

**Почему не 1.2.0**

SemVer описывает совместимость API для разработчиков. Здесь API для пользователя —
это программа целиком, и она переписана. Считать это «небольшим обновлением» значит
обесценивать объём работы и сбивать ожидания: человек должен понимать, что у него
новая программа.

**Что это даёт**

- Версия честно отражает масштаб: другая платформа, переписанный интерфейс, новая
  загрузка изображений.
- Линия выпусков разделяется: ветка 1.x — это старая оболочка на WPF, 2.x — новая.
  Запутаться в версиях невозможно.
- Обновление выглядит как событие: крупные заметки, скриншоты, подробный разбор.

**Что делаем**

- Номер версии поднимается один раз, в момент выпуска. До этого в коде остаётся
  текущая версия.
- Формат проекта не меняется: проекты, созданные в 1.x, открываются в 2.x. Это
  проверяется тестом совместимости, а не обещанием.
- Имена файлов при выгрузке не меняются: печатный сайт ничего не заметит.
