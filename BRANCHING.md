# Ветки, версии и язык

Модель: `master` — версия, доступная пользователям; `integration/2.0` — кампания 2.0.0;
короткие ветки задач от неё. Релиз собирается только из `master`.

Основание: [0003](docs/decisions/0003-branching-model.md).

---

## 1. Ветки

| Ветка | Содержимое | Откуда и куда |
|---|---|---|
| `master` | версия, доступная пользователям | только через пулреквест с подтверждением |
| `integration/2.0` | кампания 2.0.0 | приёмка задач, выпуск |
| `feature/*` | новая функция | от `integration/2.0`, обратно в неё |
| `fix/*` | ошибка | от `integration/2.0`, обратно в неё |
| `refactor/*` | изменение структуры без изменения поведения | от `integration/2.0`, обратно в неё |
| `chore/*` | пайплайн, документация, инструменты | от `integration/2.0`, обратно в неё |
| `optimization/*` | работы по производительности с замером до и после | от `integration/2.0`, обратно в неё |
| `spike/*` | эксперимент, результат — измерения | может не сливаться |
| `hotfix/*` | исправление установленной версии | от `master`, в `master` и в `integration/2.0` |

Ветка удаляется после слияния. Автоудаление включено:
`Settings → General → Pull Requests → Automatically delete head branches`.

## 2. Какие ветки проверяет CI

`.github/workflows/ci.yml` слушает `push` только у перечисленных префиксов, а также
`pull_request` в `master` и `integration/**`.

| Ветка | `push` проверяется |
|---|---|
| `integration/**` | да |
| `feature/**`, `fix/**`, `hotfix/**` | да |
| `refactor/**`, `chore/**`, `spike/**`, `optimization/**` | да |
| любое другое имя | нет |

Ветка вне списка не проверяется: зелёного статуса у неё нет. Новый префикс
добавляется в `ci.yml` тем же коммитом, что и первая ветка с этим префиксом.

## 3. Схема работы

Задача:

```
integration/2.0 ──► fix/что-то ──► проверки ──► integration/2.0
```

Выпуск:

```
integration/2.0 ──► версия в csproj ──► пулреквест ──► master ──► релиз
```

Исправление установленной версии:

```
master ──► hotfix/что-то ──► master (релиз)
                        └──► integration/2.0
```

Критерий `hotfix/*`: установленная версия не позволяет выполнить работу. Остальные
исправления входят в ближайший релиз.

## 4. Требования

1. `master` в любой момент соответствует рабочей версии.
2. Ветка удаляется после слияния.
3. Перед слиянием выполняются проверки из [BUILD.md](BUILD.md), раздел 3.
4. Один коммит — одна причина изменения: несвязанные области ведутся отдельными
   коммитами, чтобы ревью, `bisect` и `revert` работали по областям.
5. Имя файла при выгрузке и формат проекта не изменяются без отдельного решения.

## 5. Версии

Формат `MAJOR.MINOR.PATCH`.

| Изменение | Номер |
|---|---|
| Исправление | `PATCH` |
| Новая функция | `MINOR` |
| Смена платформы или переписанный интерфейс | `MAJOR` |

Версия записывается в `src\PhotoBook.Desktop.Avalonia\PhotoBook.Desktop.Avalonia.csproj`
и в тег релиза `v<версия>`. Номер поднимается один раз, в момент выпуска. Сборка
отказывается собирать версию, для которой уже существует тег.

Номер 2.0.0 обоснован в [0002](docs/decisions/0002-version-2.0.0.md).

## 6. Язык

| Что | Язык |
|---|---|
| Текст интерфейса, заметки релизов, документация | русский |
| Сообщения коммитов, пулреквесты, код и комментарии в коде | английский |

Всё, что попадает в репозиторий, пишется от лица проекта: без упоминаний инструментов,
участников работы и служебных пометок. Личные заметки ведутся вне репозитория.
