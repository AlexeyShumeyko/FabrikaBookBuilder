# Ветки и выпуск

Модель: `master` — версия, доступная пользователям. `integration/2.0` — работа по
переносу интерфейса. Сборка релиза выполняется только из `master`.

Основание: [0003](docs/decisions/0003-branching-model.md).

---

## 1. Ветки

| Ветка | Содержимое |
|---|---|
| `master` | версия, доступная пользователям |
| `integration/2.0` | работа по переносу интерфейса |
| `feature/*`, `fix/*`, `refactor/*`, `chore/*`, `spike/*` | одна задача |
| `hotfix/*` | исправление для установленной версии |

Ветка задачи создаётся от `integration/2.0` и сливается обратно в неё. Ветка
`hotfix/*` создаётся от `master` и сливается в обе ветки.

## 2. Префиксы

| Префикс | Назначение |
|---|---|
| `feature/<что>` | новая функция |
| `fix/<что>` | ошибка |
| `hotfix/<что>` | ошибка в установленной версии |
| `refactor/<что>` | изменение структуры кода без изменения поведения |
| `chore/<что>` | пайплайн, документация, инструменты |
| `spike/<что>` | эксперимент, который может не быть включён |

Ветка `spike/*` не обязательно сливается: её результат — измерения для решения.

## 3. Схема

Задача:

```
integration/2.0 ──► fix/что-то ──► проверки ──► integration/2.0
```

Выпуск:

```
integration/2.0 ──► версия в csproj ──► pull request ──► master ──► релиз
```

Исправление установленной версии:

```
master ──► hotfix/что-то ──► master (релиз)
                        └──► integration/2.0
```

Критерий исправления по пути `hotfix/*`: установленная версия не позволяет выполнить
работу. Иные исправления входят в ближайший релиз.

## 4. Требования

1. `master` соответствует рабочей версии в любой момент.
2. Ветка удаляется после слияния.
3. Перед слиянием выполняются проверки из [BUILD.md](BUILD.md), раздел 3.
4. Шаг рефакторинга равен одному коммиту и является точкой отката.
5. Волны 0–2 не изменяют поведение: см. `doc/ROADMAP.md`.
6. Имя файла при выгрузке и формат проекта не изменяются без отдельного решения.

Автоудаление веток: `Settings → General → Pull Requests → Automatically delete head
branches`.

## 5. Версии

Формат `MAJOR.MINOR.PATCH`.

| Изменение | Номер |
|---|---|
| Исправление | `PATCH` |
| Новая функция | `MINOR` |
| Смена платформы или переписанный интерфейс | `MAJOR` |

Версия записывается в `src\PhotoBook.Desktop.Wpf\PhotoBook.Desktop.Wpf.csproj` и в тег релиза `v<версия>`. Номер
поднимается один раз, в момент выпуска. Сборка релиза отказывается собирать версию,
для которой уже существует тег.

Номер следующего релиза определён в [0002](docs/decisions/0002-version-2.0.0.md).
